# 03. 前端界面与交互设计

本文档定义**普通高频流程如何走短路径、异常与受限事实放在哪里提示、引导用户作出什么决定，以及前端状态归属**。关于取消、翻页、并发冲突判定与迁移五态结果的权威规则，统一遵循 [02-database-engine-design.md](./02-database-engine-design.md)，本文件不重复定义底层语义。

---

## 1. 交互原则：高频操作走短路径

1. **零多余点击的高频路径**：
   - 双击对象树中的表 → 直接打开数据浏览标签页；
   - 在 SQL 编辑器按 `Ctrl+Enter` → 直接在下方显示结果网格；
   - 普通查询成功**绝不弹窗打扰**，仅在底部状态栏静默刷新耗时与行数；
   - SQL 变更预览、参数绑定表与执行明细默认收起，**按需展开**。
2. **上下文始终可辨**：
   - 顶部上下文条与 Tab 标题始终清晰显示“当前连接（含环境色标：红=生产 / 琥珀=测试 / 绿=开发）→ 目标库 / Schema”，避免看错库误操作。
3. **会改变下一步决定的事实，直接放在操作旁**：
   - 某张表不能改删、或仅支持新增、或不支持整批事务提交时，**直接在网格工具栏旁给出简明原因**，不等用户点保存才报错；
   - 改表计划不能整体回滚（如 MySQL 隐式提交）时，在点击“应用”前的确认区直接明示边界；
   - 一旦发生会话丢失、提交结果未知或改表确认丢失，直接给出清晰下一步动作（“重新连接”或“先刷新核对数据/结构”），绝不诱导盲目重试。
4. **四库语义一致、按能力裁剪**：
   - PG / MySQL / MariaDB / SQLite 共用相同的按钮图标与含义；
   - 数据库不支持的对象类型（如 SQLite 的 Schema / 序列）直接不出现在对象树，前端不散落“按库名/版本号 `if/else`”的硬编码，全部消费后端返回的 `Capabilities` 与 `TableEditability`。

## 2. 主工作台布局（`dockview-vue`）

```text
+----------------------------------------------------------------------------------+
| [连接+] [新建查询] [表设计] [导入/导出]  |  prod-pg (红标) / app_db / public [切换] |
+----------------------+-----------------------------------------------------------+
| [搜索对象 Ctrl+K]     | [Query 1 *] [users (表数据)] [orders (表结构)]  [+]        |
|----------------------|-----------------------------------------------------------|
| ▼ prod-pg (PG 16)    |  1 | SELECT u.id, u.name, o.total                        |
|   ▼ app_db           |  2 | FROM users u                                         |
|     ▼ public         |  3 | JOIN orders o ON o.user_id = u.id                    |
|       ▼ 表 (42)      |  4 | WHERE u.status = 'active';                           |
|         • users      |-----------------------------------------------------------|
|         • orders     | [▶ 执行 Ctrl+Enter] [▶▶ 全部] [■ 停止] [美化] [EXPLAIN]     |
|       ▶ 视图 (5)      |-----------------------------------------------------------|
|       ▶ 序列 (8)      | [结果 1 (1000行)] [消息] [执行计划]                        |
| ▶ local-mysql (8.0)  | +----+----------+----------+----------------------------+ |
| ▶ dev.sqlite         | | id | name     | total    | created_at                 | |
|                      | | 1  | 张三     | 128.50   | 2026-11-24 10:12:00        | |
|                      | | 2  | 李四     | NULL     | 2026-11-24 11:05:31        | |
|                      | +----+----------+----------+----------------------------+ |
|                      | [< 第 1 页 >] [1000行/页] [筛选] [+新增] [导出]             |
+----------------------+-----------------------------------------------------------+
| 连接: SSH+只读 | 会话: 空闲 | 耗时: 14ms | 选中 3 格 (Sum: 385.5)                |
+----------------------------------------------------------------------------------+
```

- **高密度桌面风**：数据网格严格单行（行高 `28px`，`#` 行号列左吸顶固定、支持横向滚动与采样自动列宽）、对象树行高 `24px`，等宽字体呈现 SQL、数值与 DDL，支持浅色 / 深色主题。
- **可滚动完整值浮窗（Value Inspector Modal）**：双击单元格（或选中按 `Space`）弹出独立纵向滚动的浮窗查看大文本、格式化 JSON 或按需流式查看/下载 BLOB，不挤占主表格横向空间。

## 3. 前端状态归属（严格遵守“不自猜后端状态”）

| Pinia Store | 负责的状态（仅限 UI 态 + 后端确认状态镜像） |
| :--- | :--- |
| `useConnectionStore` | 连接分组、连接列表、在线态、后端下发的 `Capabilities` |
| `useSchemaStore` | 左侧虚拟树已加载节点、表详情与补全字典缓存 |
| `useWorkspaceStore` | 打开的 Tab、`dockview-vue` 布局、当前在途 `execID`、以及**后端权威回报的 `SessionState`**（前端严禁自行推断事务是否已结束） |
| `useGridEditStore` | 按 `tabId` 暂存的未提交草稿（增/改/删单元格）、Undo/Redo 栈、后端生成的同源 `ChangePlan` 预览数据 |
| `useTransferStore` | 后端事件推送的导入/导出进度与任务取消句柄 |
| `useSettingsStore` | 主题、字体、默认页大小、不可见空白符显示开关、快捷键方案、生产安全确认开关、Linux 渲染模式 |

> `frontend/bindings/` 由 `wails3 generate bindings` 自动生成，禁止手改；`frontend/src/api/` 仅做统一错误码分派与事件监听清理。

## 4. 核心流程与异常决策落点

### 4.1 对象浏览与连接管理
- **连接配置**：支持常规 / SSL / SSH / 高级四页签；“只读模式”复选框旁明确注明：**此开关为客户端防误写护栏（SQLite 可本地只读打开），生产强只读请以数据库账号实际权限为准**。
- **对象树**：使用 `@tanstack/vue-virtual` 虚拟滚动渲染展平树，仅渲染驱动能力声明的对象分组；右键菜单提供打开数据、设计表结构、复制 DDL、快速生成语句模板、导入/导出、清空/删除表（删表需输入表名确认）。

### 4.2 SQL 编辑器（CodeMirror 6）
- **日常短路径**：自动按当前连接加载 PG / MySQL / MariaDB / SQLite 方言高亮；切换库/Schema 时后台拉取补全字典支持表名、列名与表别名（`u.`）补全；选中文本执行选中，未选中按光标定位单条执行（`Ctrl+Enter`），`Ctrl+Shift+Enter` 执行全部。
- **高危 SQL 保护**：对生产色标连接执行无 `WHERE` 的 `UPDATE`/`DELETE`、`DROP`、`TRUNCATE` 时，在执行前弹出确认框展示目标连接名与待执行语句。
- **停止执行与三类异常的落点区分**（底层语义见 [02 第 2 节](./02-database-engine-design.md#2-权威规则一取消执行断线与重连internalsession)）：

| 后端确认状态 | 展示位置 | 给用户的明确下一步决策 |
| :--- | :--- | :--- |
| **语句已取消**（`ERR_STATEMENT_CANCELED`） | 结果区顶部温和信息条（不弹窗） | 说明“语句已取消，原会话存活”；若 PG 处于 `AliveFailedTx`，在信息条旁直接放置 **`[执行 ROLLBACK]`** 按钮。 |
| **原会话已丢失**（`ERR_SESSION_LOST`） | 编辑器顶部醒目橙色横幅 + 状态栏红点 | 明确说明“原连接已中断或停止复用，临时表与未提交事务已失效”，提供 **`[在新会话中重连]`** 按钮，由用户确认后继续。 |
| **提交结果未知**（`ERR_COMMIT_OUTCOME_UNKNOWN`） | 阻断式高危警示框 + 持久横幅 | 明确说明“`COMMIT` 已发出但确认丢失，无法判断是否已提交”，**不提供自动重试按钮**，引导用户先开只读查询核对数据。 |

### 4.3 数据结果网格（TanStack Table + Virtual）
1. **翻页与状态提示**（底层语义见 [02 第 3.2 节](./02-database-engine-design.md#32-双路径翻页语义表浏览-vs-编辑器任意-sql)）：
   - **表浏览 Tab**：实时查库、按稳定键排序分页，支持顶部 `WHERE` 快捷筛选条与服务端列排序；
   - **编辑器结果 Tab**：从后端一次性快照切片翻页。触及容量上限时，在翻页条旁显示轻提示“仅预览前 N 行，如需全量请导出”；快照过期（`ERR_RESULT_EXPIRED`）时在翻页区直接给出 **`[重新执行 SQL]`** 按钮（绝不静默重跑）。
2. **单元格保真渲染、智能列宽与框选复制**：
   - 单元格保持简洁纯文字无胶囊排版：`NULL` 以纯灰色斜体显示、空串以无框淡灰 `""` 显示、有值内容一律使用主色；底部提供「`¶ 空白符`」开关按需显示空格 `·` / 制表符 `→` / 换行 `↵` / 零宽字符（复制与导出严格保真原文）；`BIGINT`/`DECIMAL` 按前 100 行采样自动扩宽（默认上限 `420px`）并支持双击分隔线 Auto-Fit；单击单元格在底栏预览完整值，双击弹出可滚动浮窗查看长文本/JSON/BLOB；支持类 Excel 矩形框选复制为 TSV / CSV / JSON / SQL `INSERT`。
3. **网格写入提示放在工具栏旁**（底层判定见 [02 第 4 节](./02-database-engine-design.md#4-权威规则三网格写入与并发冲突检测internalchangeset)）：
   - 前端直接消费后端返回的 `TableEditability`：
     - **只读连接 / 无写权限**：锁定全部编辑入口，旁注“只读模式 / 无写权限”；
     - **无稳定唯一键（含 SQLite 仅隐式 `rowid` 表）**：允许点击 `[+ 新增行]`（若有写权限），锁定单元格修改与删行，旁注“无显式主键或非空唯一键，仅支持浏览与新增”；
     - **非事务存储引擎表（如 MySQL/MariaDB MyISAM）**：旁注“MyISAM 为非事务表，首版不支持整批回滚提交”，引导使用 SQL 编辑器操作；
     - **可编辑表**：改后单元格浅黄/绿/红着色，底部常驻 `已修改 N 处 | [撤销] [预览 SQL] [提交 Ctrl+S] [放弃]`；点击预览按需展开与执行 100% 同源的参数化 `ChangePlan`；若提交命中并发冲突（`ERR_CONCURRENCY_CONFLICT`），**保留草稿不清空**、高亮冲突行，引导用户刷新对比后再决定。

### 4.4 可视化表结构设计器
- 提供 **列 / 索引 / 外键 / 选项 / 触发器 / 改表计划** 6 个子页签。
- **确认前明示边界**（底层语义见 [02 第 5 节](./02-database-engine-design.md#5-权威规则四跨库改表计划与五态迁移报告)）：
  - 点击“保存应用”前，在确认面板清晰标注本次 `MigrationPlan` 的原子性级别（`可整体回滚` / `单条原子 ALTER` / `⚠️ 非事务多步，中途失败无法整体回滚`），SQLite 额外列出受影响的依赖视图与 `INSTEAD OF` 触发器清单；DDL 明细可一键展开审阅。
- **执行后五态清晰汇报**：
  - 全部成功时温和刷新表结构；
  - 若中途失败或中断，弹出 `MigrationReport` 面板，逐条以徽章区分 **`已生效` / `已回滚` / `确认失败` / `未执行` / `结果未知`**；
  - 一旦任一步为 **`结果未知`（`StepOutcomeUnknown`）**，**隐藏“重试”按钮**，置顶高亮 **`[刷新并核对当前表结构]`** 操作。

## 5. 快捷键规范（预留 macOS `Cmd` 映射）

通过 `composables/useShortcuts.ts` 将 `Mod` 在 Windows/Linux 映射为 `Ctrl`，后续在 macOS 自动映射为 `Cmd`：

| 快捷键 | 功能 |
| :--- | :--- |
| `Mod + N` | 当前连接下新建 SQL 查询 Tab |
| `Mod + K` | 全局快速跳转（连接 / 表 / 视图 / 命令） |
| `Mod + Enter` | 执行选中 SQL / 光标所在单条 SQL |
| `Mod + Shift + Enter` | 顺序执行编辑器内全部 SQL |
| `Mod + .` / `Esc` | 取消当前正在执行的查询 |
| `Mod + Shift + F` | 格式化 SQL |
| `Mod + S` | 保存查询，或在网格/表设计器中触发提交 |
| `Mod + W` | 关闭当前 Tab |
| `F5` | 刷新当前网格或对象树节点 |
| `Mod + Shift + N` | 将选中单元格置为 `NULL` |
| `Mod + /` | 注释 / 取消注释当前行 |
